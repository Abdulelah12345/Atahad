# واجهات تعهّد المشي

تم تطبيق واجهات المشي فوق تصميم `main` الأزرق والكحلي والذهبي، مع دعم الوضعين الفاتح والداكن.

## ما أضيف

- خيار «مجموع خطوات اليوم» في إنشاء العادة من «تعهّد جديد» ومن نموذج العادة المعتاد. لا يظهر ضمن الأهداف ذات الخطة أو أهداف المجموعات.
- هدف يومي من ١٠٠ إلى ١٠٠٬٠٠٠ خطوة، واقتراحات سريعة ٣٠٠٠/٥٠٠٠/٨٠٠٠، مع قبول الأرقام العربية والفارسية.
- فحص الربط وحفظ نتيجته في الباك إند قبل التفعيل. فشل حفظ الفحص يمنع اعتبار الربط جاهزًا.
- اختيار «ربط خطوات الجوال» أو «صورة خطوات اليوم» قبل البداية. الهدف وطريقة الإثبات ثابتان بعد التفعيل.
- خيار صريح للانتقال إلى تعهّد بالمؤقّت؛ الدقائق لا تُحوّل إلى خطوات ولا يُدّعى أنها تثبت الحركة.
- صفحة `/walking/:weekId` لعرض الهدف، المجموع، آخر مزامنة، حالة الإنجاز ورفع الصورة، وصفحة `/walking` لتعهّدات المشي النشطة.
- الوصول من بطاقة اليوم، قائمة الإثباتات، تفاصيل إثبات المشي، قائمة العادات، وشاشة قفل الحساب.
- عرض بيانات أمس ضمن مهلة المزامنة؛ يتم اختيار الأسبوع الصحيح من سجل التعهّد، حتى عند الانتقال إلى أسبوع جديد.
- رفع PNG/JPEG بحجم حتى ٢٫٢ ميغابايت، مع معاينة وتأكيد ظهور التاريخ والمجموع قبل إرسالها للمراجعة. تمنع الواجهة إعادة رفع صورة سبق تقديمها.

## القراءة والمزامنة

يستخدم `walking_health.dart` مكتبة `health 13.3.1` مع قراءة `STEPS` فقط. تم اختيار هذا الإصدار لتوافقه مع مكتبة حفظ تسجيل الدخول الحالية؛ لم تتم ترقية أو تغيير مخزن بيانات الدخول.

- أندرويد: Health Connect، مع فحص توفر الخدمة وصلاحية قراءة الخطوات وإذن التعرّف على النشاط.
- آيفون: HealthKit. البيانات الفارغة تُعرض كحالة غير محسومة؛ لا يُفترض أن طلب الإذن الناجح يعني منح إذن القراءة.
- لا توجد طلبات لكتابة بيانات الصحة أو موقع المستخدم ضمن ميزة المشي.
- تُطلب صلاحية الصحة صراحة من زر فحص الربط/المزامنة. القراءة التلقائية لا تطلب صلاحيات جديدة.
- تتم المزامنة عند فتح صفحة المشي والعودة للتطبيق، ومرة كل دقيقة أثناء ظهور صفحة المشي والتطبيق في المقدمة. لا توجد خدمة خلفية تجمع الخطوات داخل Flutter؛ مصدر الخطوات هو نظام الصحة.
- تُحسب الفترة من منتصف الليل بتوقيت الرياض إلى الآن/نهاية اليوم، حتى إن كان توقيت الهاتف مختلفًا. يستخدم التطبيق مجموع اليوم، ولا يجمع إجماليات القراءات المتكررة.
- يُرسل معرّف تثبيت عشوائي محفوظ محليًا؛ لا يُرسل معرّف العتاد إلى الباك إند.
- يُطلب استبعاد الإدخالات اليدوية من المكتبة، لكن ذلك ليس ضمانًا ضد التلاعب أو لكل اختلافات مصادر Android. مستوى الثقة يظل `DEVICE_REPORTED` كما هو موضح في وثيقة الباك إند.

عند فشل القراءة أو الاتصال تبقى آخر قراءة ظاهرة. عدم وجود بيانات يعرض «—» بدل صفر، وفشل تحميل الصفحة أول مرة يعرض إعادة المحاولة دون اختلاق هدف. المتصفح لا يقرأ HealthKit/Health Connect؛ يوضّح ذلك ويتيح بديل الصورة.

## إعدادات الجوال

أندرويد: تمت إضافة `READ_STEPS` و`ACTIVITY_RECOGNITION`، والتحويل إلى `FlutterFragmentActivity`، ووجهة مستقلة لشرح استخدام صلاحية الصحة. الحد الأدنى للبناء Android API 26 (أندرويد ٨) بسبب المكتبة؛ الربط عبر Health Connect يحتاج دعم الخدمة على الجهاز، ويمكن اختيار الصورة عند غيابه.

آيفون: تمت إضافة وصف قراءة الصحة والصور وملف HealthKit entitlements وربطه بإعدادات Debug/Profile/Release. حد iOS الحالي 15.5 لم يتغير. يلزم أن يدعم حساب التوقيع وملف provisioning ميزة HealthKit عند البناء على ماك.

إعداد API_BASE_URL وعنوان الباك إند الفعلي يبقيان وفق إعدادات المشروع الحالية. تحديث جداول الباك إند موضح في `walking-steps.md` وملف SQL المرفق؛ لم يتم تشغيله على بيانات المستخدم.

## التحقق

الاختبارات تغطي صحة اليوم بتوقيت الرياض، الأرقام العربية، فشل فحص الربط، الصفر الحقيقي، المنصات غير المدعومة، فقدان الاتصال، إبقاء القراءة السابقة، حجم الصورة، وحالات منع إعادة رفعها.

تم بناء معاينة Web تجريبية وفحص الوضعين الفاتح والداكن. المعاينة تستخدم بيانات وهمية خارج ملفات تشغيل التطبيق الفعلية، ولا تصل إلى حساب أو قاعدة بيانات المستخدم.

نتيجة التحقق بتاريخ ٢٦ أكتوبر ٢٠٢٦: **٢٦ اختبار واجهة ناجحًا** و**٢١ اختبار تكامل للباك إند ناجحًا** بعد الربط. التحليل دون أخطاء، مع بقاء تحذير قديم عن متغير غير مستخدم في شاشة مطابقة المجموعات. نجح بناء Web النهائي.

**لم يتم اختبار قراءة حساسات على جهاز فعلي أو بناء APK/IPA في هذه البيئة.** فحص Flutter وجد أن Android SDK غير مثبت، ولا تتوفر بيئة ماك/Xcode. لذلك يبقى اختبار الصلاحيات والقراءات والتوقيع على أندرويد وآيفون خطوة لازمة قبل النشر.
