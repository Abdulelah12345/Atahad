# دليل تطوير البروف

## النطاق

- طرق الإثبات الأساسية بقيت `PHOTO`, `QUIZ`, `TIMER`, `LOCATION`.
- `BEFORE_AFTER` دليل إضافي داخل المحاولة وليس قيمة جديدة لـ `proofMethod`.
- المحاولات الجديدة متاحة للصورة والاختبار والمؤقت. ربط الزيارة بالمحاولة ذات الصور الإضافية **متروك للزميلة**؛ يمنع بدء محاولة LOCATION جديدة حتى يكتمل الربط، ويستمر فلو الزيارة السابق مستقلاً.
- لا يشمل التغيير محادثة صوتية أو مراقبة فيديو مستمرة أو البحث عن كتب أو تحليل كتاب كامل.

## التشغيل

ضع المفتاح في متغير البيئة `OPENROUTER_API_KEY`، ولا تضفه إلى المستودع. القيم الاختيارية:

```text
OPENROUTER_TEXT_MODEL=google/gemma-4-26b-a4b-it:free
OPENROUTER_VISION_MODEL=google/gemma-4-26b-a4b-it:free
OPENROUTER_TIMER_MODEL=google/gemma-4-26b-a4b-it:free
```

`AI/OpenRouterClient` يقبل أسماء تنتهي بـ `:free` أو `openrouter/free` فقط. لا يوجد تحويل مدفوع عند فشل الطلب. الأسعار والتوفر يحددهما المزود، ولا يتضمن الكود ضمان استمرار نموذج بعينه.

جميع كلاسات الذكاء أصبحت في باكج `AI`. بقيت واجهة `AiService` وخصائصها القديمة للتوافق مع ميزات الفريق السابقة. تحليل صور البروف والكويز ورسائل المؤقت تستخدم اتصال OpenRouter المشترك.

بدون المفتاح: المؤقت يعمل برسائل بديلة؛ الصور تصعد للأدمن؛ تعذر توليد الاختبار لا يستهلك محاولة. لا يقبل الدليل تلقائيًا بسبب تعطل الذكاء.

واجهة مرجعية للتجربة: `http://localhost:8080/proof-session.html`. تسجل الدخول بالبريد وكلمة المرور، وتدخل رقم الأسبوع ورقم المهمة إن كانت لهدف. واجهة الاختبار تستخدم HTTP Basic وفق إعداد المشروع الحالي، وتحتفظ ببيانات الدخول في الذاكرة فقط. الكاميرا تحتاج HTTPS أو localhost وإذن المستخدم.

## دورة المحاولة

1. اختياريًا اطلب تذكرة `BEFORE` وارفع الصورة، ثم ابدأ خلال خمس دقائق.
2. ابدأ المحاولة، ويرجع `proofId`. الطريقة الأساسية تستمد من المهمة أو العادة، والملكية والأسبوع والحالات تفحص في السيرفس المركزي الحالي.
3. أرسل الدليل الأساسي عبر `submit`، أو استخدم إجراءات المؤقت. صور الصفحات لا تلزم الاختبار.
4. إذا اختيرت صور إضافية من البداية، ارفع `AFTER` وأرسل معرفه، أو استخدم `skip-photos` إذا قررت المتابعة بدونها.
5. أي دليل مقبول يقبل المحاولة مرة واحدة. وجود دليل منتظر يؤخر الرفض والتصعيد. فشل دليل لاحق لا يلغي نجاحًا محفوظًا.

مثال بدء مؤقت مع صور:

```json
{"goalTaskId": 12, "beforeAfter": true, "beforeCaptureId": 7, "targetMinutes": 25}
```

لعادة، احذف `goalTaskId`. المدة بين دقيقة وستمائة دقيقة، وتثبت عند بدء المحاولة. الاقتراح اختياري وقابل للتعديل قبل البداية.

## أهم المسارات

كلها تتطلب MEMBER وتفحص ملكية البيانات. لا يرسل العميل معرف مستخدم جديدًا إلى مسارات المحاولة؛ يؤخذ من جلسة الدخول.

| الطريقة | المسار | المحتوى |
|---|---|---|
| GET | `/api/v1/proof-attempt/suggest/{weekId}?goalTaskId=12` | اقتراح المدة |
| POST | `/api/v1/proof-attempt/start/{weekId}` | بيانات البداية |
| GET | `/api/v1/proof-attempt/{proofId}` | الحالة والأدلة والمؤقت ومعرفات الأسبوع والمهمة |
| POST | `/api/v1/proof-attempt/capture?kind=BEFORE` | إصدار تذكرة كاميرا |
| POST | `/api/v1/proof-attempt/capture?kind=AFTER&proofId=1` | إصدار تذكرة النهاية |
| POST | `/api/v1/proof-attempt/capture/{id}` | `token`, `imageData` |
| POST | `/api/v1/proof-attempt/{proofId}/submit` | `evidenceData` |
| POST | `/api/v1/proof-attempt/{proofId}/after` | `afterCaptureId` |
| POST | `/api/v1/proof-attempt/{proofId}/skip-photos` | جسم فارغ |
| POST | `/api/v1/proof-attempt/timer/{id}/{action}` | حسب الإجراء |
| POST | `/api/v1/quiz/create/{memberId}/{weekId}?goalTaskId=12` | `proofId`, `captureIds` اختياري |

أنواع تذكرة الكاميرا: `BEFORE`, `AFTER`, `PHOTO`, `PAGE`. `imageData` صورة JPEG أو PNG بصيغة data URL، حتى 2MB بعد فك Base64 و16 مليون بكسل. لا ترسل ملفات أو روابط خارجية مباشرة. `PHOTO` يرسل معرف الالتقاط كنص في `evidenceData`؛ الكويز يرسل مثل `42:ABCA`.

التذكرة تمنع إعادة استعمال الالتقاط وتربطه بالمالك، لكنها **لا توفر attestation لمستشعر الكاميرا**. واجهة المرجع لا تحتوي على رفع من المعرض؛ السيرفر وحده لا يستطيع استبعاد عميل معدل يرسل صورة قديمة داخل التذكرة.

## الاختبار

- أربعة أسئلة سهلة، ثلاثة خيارات لكل سؤال؛ النجاح بثلاث إجابات صحيحة.
- تنتهي الصلاحية بعد ساعة من إنشاء الاختبار، وإعادة واحدة فقط لكل مهمة/عادة وأسبوع ويوم نشاط.
- طلب اختبار صالح غير مستخدم يعيد الموجود ولا يستهلك محاولة جديدة.
- صور الصفحات اختيارية: أول عدم وضوح يطلب إعادة تصوير واحدة، والثاني يحاول أسئلة عامة. فشل التوليد لا يستهلك محاولة.
- الإجابات الصحيحة والأسئلة بصيغتها الخام المخزنة لا تسلسل إلى JSON. الرد يحتوي السؤال والخيارات فقط.
- الأسئلة العامة لا تثبت قراءة فصل معين، ولا يوجد تنزيل تلقائي للكتاب في هذه الإضافة.

## المؤقت

الإجراءات: `state`, `pause`, `resume`, `finish`, `extend`, `feedback`.

التمديد: `{"minutes":5}` بعد اكتمال المدة الأصلية. التقييم: `{"feedback":"EASY"}` أو `OK` أو `TIRING`. التقييم لا يؤثر على النجاح. يحتسب وقت السيرفر فقط، ويستثنى الإيقاف الصريح. الجلسة مستمرة في الخلفية وانقطاع الاتصال؛ الوقت لا يثبت جودة النشاط أو انتباه المستخدم.

تنتهي الجلسة عند منتصف الليل بالرياض. لا يحمل الوقت الناقص لليوم التالي. إذا تحقق المطلوب فعليًا قبل الحد، يقبل ولو وصلت قراءة الحالة بعده. المؤقت لا يقبل عدد دقائق يدخله العميل كإثبات. إكمال الأصل يحتسب مرة واحدة حتى مع التمديد.

## نقطة التسليم الخاصة بالموقع

لم يتغير حساب المسافة أو مدة الزيارة أو الإغلاق التلقائي. `PlaceVisitService` تغير فقط لإضافة `checkMember` في مسارات المستخدم. الإغلاق المجدول يظل عبر الخدمة الداخلية دون اشتراط مستخدم مسجل.

عند ربط الزيارة لاحقًا، يجب إعادة استخدام `proofId` للمحاولة الجديدة وتمرير نتيجة الزيارة إلى `ProofOutcomeService.primary`، مع الاحتفاظ بالزيارة الحالية ومنع إنشاء بروف منافسة لليوم نفسه. لا تفعل الواجهة خيار الصور للموقع قبل اكتمال هذا الربط واختباره.

## قاعدة البيانات والتوافق

أضيفت جداول `proof_evidence`, `proof_capture`, `timer_session` وحقول المحاولة في `Proof` وحقول المحاولات والدرجة في `Quiz`. حقل صورة البروف أصبح `MEDIUMTEXT`. إعداد المشروع الحالي `ddl-auto=update` ينشئ التغييرات عند التشغيل؛ راجع مخطط البيئة المشتركة قبل نشر النسخة عليها. البروف القديمة تبقى قابلة للقراءة. تحديث وحذف بروف المحاولات الجديدة محظوران عبر CRUD القديم؛ تعامل معها بمسارات الجلسة.

## التحقق

مجموعة الاختبارات تستخدم H2 معزولة عن قاعدة الفريق. تشمل صلاحيات الفلاتر، ملكية معرف العضو، تجميع الأدلة، العداد والنقاط عبر HTTP، المؤقت وحد اليوم، أسئلة الاختبار وإعادة التصوير، تزامن قرارين، وطلب OpenRouter نحو مزود HTTP محلي بديل.

التشغيل:

```powershell
.\mvnw.cmd '-Dtest=*Test,!AtahadApplicationTests' test
```

يستثنى اختبار السياق القديم لأنه يعتمد إعداد قاعدة التطوير، ويغطي اختبار `ProofHttpIntegrationTest` تحميل التطبيق كاملًا بقاعدة معزولة. لم يختبر مزود AI حي لغياب المفتاح، ولم تختبر كاميرا جهاز حقيقي أو قاعدة MySQL فعلية في هذه الجولة.
