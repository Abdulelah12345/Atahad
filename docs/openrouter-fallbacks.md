# بدائل OpenRouter المجانية

الترتيب الافتراضي للنصوص والصور ورسائل المؤقت:

1. النموذج الأساسي في متغير التشغيل، افتراضيًا `google/gemma-4-26b-a4b-it:free`.
2. `google/gemma-4-31b-it:free`.
3. `nvidia/nemotron-3.5-super-vl:free`.

يتولى التطبيق تجربة النماذج بالتتابع، بطلب مستقل لكل نموذج. ينتقل للتالي عند فشل HTTP أو الاتصال، أو رد فارغ/مبتور/غير صالح، أو قرار `ESCALATED` غير حاسم. أول قرار `ACCEPTED` أو `REJECTED` صالح مع سبب يوقف السلسلة فورًا. لا نعيد قرار الرفض عبر نموذج آخر بحثًا عن القبول.

تتم إحالة الإثبات أو العذر للأدمن فقط بعد استنفاد البدائل دون قبول أو رفض حاسم. عند وجود تحليل غير حاسم صالح يحتفظ التطبيق بسببه للمراجعة؛ وإلا يستخدم رسالة التعذر الحالية. لا يتغير القرار المحفوظ سابقًا تلقائيًا بمجرد إعادة تشغيل التطبيق.

للكويز، الصيغة غير الصالحة أو `READABLE: NO` تدفع لتجربة البديل. إذا لم ينجح أي بديل، يرجع طلب إعادة التصوير عند وجود نتيجة عدم وضوح، أو التعذر المعتاد عند غياب رد صالح. التوليد الفاشل لا ينشئ اختبارًا ولا يستهلك محاولة. البرومبت الجديد المعتمد للنقاش لم يُطبّق ضمن هذا التغيير.

يوجد حد أقصى ثلاثة نماذج مختلفة، بمهلة 25 ثانية لكل طلب وحد اتصال 8 ثوانٍ؛ لا يوجد انتظار أو إعادة طلب للنموذج نفسه. زمن محاولات الشبكة يصل عادةً إلى نحو 75 ثانية في أسوأ حالات المهلة، مع بقاء مهلة الفرونت الحالية 120 ثانية. هذا انتقال داخل التطبيق بدل الاقتصار على تحويل الأخطاء الذي ينفذه OpenRouter.

متغيرات البدائل اختيارية، ولا يحتاج المفتاح أو متغيرات النماذج الأساسية الحالية إلى تغيير:

- `OPENROUTER_TEXT_FALLBACKS`
- `OPENROUTER_VISION_FALLBACKS`
- `OPENROUTER_TIMER_FALLBACKS`

قيمة كل منها الافتراضية: `google/gemma-4-31b-it:free,nvidia/nemotron-3.5-super-vl:free`.

تُحذف التكرارات والبدائل المدفوعة، ويُمنع الطلب عند ضبط نموذج أساسي مدفوع. أي صور في الطلب تفرض سلسلة الرؤية، وتُرسل الصور نفسها وبترتيبها لكل بديل. يجب أن تدعم بدائل الرؤية المخصصة الصور. البدائل الافتراضية تدعمها وفق كتالوج OpenRouter المباشر وقت التنفيذ في 25 أكتوبر 2026.

تبديل النماذج لا يتجاوز حد الحساب اليومي أو انقطاع الشبكة. سجلات التشغيل تعرض إعداد المفتاح كحالة موجود/غير موجود فقط، واسم النموذج ورقم المحاولة وسبب التعذر التقني. لا تُسجل المفاتيح أو الصور أو نصوص المستخدم.

الاختبارات المحلية تغطي فشل الأول ونجاح الثاني، والردود الفارغة وغير الصالحة، وعدم الحسم في أول نموذجين ونجاح الثالث، والتوقف عند رفض واضح، واستنفاد البدائل قبل الإحالة، وحفظ ترتيب الصور، وحد المحاولات، ومنع تسريب البيانات إلى السجل. وجود اختبار ناجح للاتصال لا يضمن صحة كل قرار مستقبلي من النموذج.
