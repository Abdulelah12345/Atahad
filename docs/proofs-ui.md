# واجهات الإثباتات والأعذار والاعتراضات

## المسار المعتمد

- من «اليوم»، الضغط على بطاقة النشاط يفتح محاولة الإثبات الحالية أو يبدأ توثيق نشاط جديد.
- تبويب «طلباتي» بجانب «اليوم» يجمع الأعذار والاعتراضات مع الفلاتر وحالة كل طلب.
- «سجل إثباتاتي» يعرض الإثباتات السابقة وتفاصيل أدلتها.
- «عندي عذر بدل الإثبات» يحدد النشاط تلقائيًا، ويمكن تقديم عذر من «طلباتي» أيضًا.
- «التبرع والمبالغ» يعرض المبالغ المعلقة والسجل ورفع صور رسالتي البنك وإحسان، أو التحقق من البريد عبر ربط Gmail الموجود في الباك إند.
- حساب الأدمن يفتح مركز المراجعة لعرض سبب القرار والأدلة والقبول والرفض، بالإضافة إلى قائمة المبالغ.

## طرق الإثبات

1. **الصورة:** تصوير مباشر بالكاميرا، دون اختيار صورة إثبات من المعرض.
2. **قبل وبعد:** اختيار إضافي عند البداية مع الصورة أو المؤقت أو الاختبار. تؤخذ صورة البداية أولًا، وصورة النهاية بعد النشاط. ظهور قبول أحد الأدلة يعتمد على نتيجة السيرفر، ويحسب النشاط مرة واحدة.
3. **الكويز:** أربع أسئلة اختيارية، والنجاح من ثلاثة. صور الصفحات اختيارية من الكاميرا؛ المهلة وعدد الإعادات يطبقهما السيرفر.
4. **المؤقت:** مدة مقترحة قابلة للتعديل قبل البداية، استراحة واستكمال، تمديد اختياري بعد المدة الأصلية، وتقييم اختياري للجلسة. الحساب والقبول من السيرفر، والعرض يتحدث أثناء تشغيل الشاشة.
5. **الموقع:** واجهة للوصول والمغادرة عبر مسارات الزيارة الحالية. حساب المسافة والمدة بقي في خدمة الموقع الموجودة. ربط قبل/بعد بالزيارة مؤجل لزميلة الموقع وفق الاتفاق.

مرفقات العذر والتبرع تقبل صور المستندات من الجهاز؛ هذا يختلف عن تصوير إثبات النشاط المباشر. الحد الحالي للصورة ٢ ميغابايت بصيغة JPEG أو PNG.

## الصلاحيات والمرفقات

- بيانات الطلبات تأتي من `/api/v1/proof-workspace/my` بحسب المستخدم المسجل.
- مرفقات العذر والتبرع تحفظ كمرجع قصير `capture:<id>`، ويجري فحص الملكية عند قراءتها واستخدامها.
- أزرار تعديل الطلب وحذفه والاعتراض تعرض وفق الحالة؛ وتبقى التشييكات النهائية داخل السيرفس.
- فتح مراجعة اعتراض للأدمن يستدعي مسار بدء المراجعة قبل فتح تفاصيله.
- واجهة العضو لا تطلب كتابة معرف المستخدم أو النشاط يدويًا.

## تشغيل النسخة الفعلية على Chrome

1. شغّل قاعدة البيانات، ثم أعد تشغيل `AtahadApplication` لتحميل الكنترولرات الجديدة.
2. من مجلد `frontend`، شغّل `flutter pub get` مرة واحدة لتحميل مكتبات الكاميرا والموقع والمرفقات.
3. أوقف تشغيل Flutter القديم بالحرف `q`، ثم شغّله مجددًا على المنفذ 5173 بنفس حساب التطوير الذي تستخدمه. لا تحفظ كلمة المرور داخل ملفات المشروع.

```powershell
$loginPassword = Read-Host "Password"
flutter run -d chrome --web-port 5173 --web-hostname localhost --dart-define=DEV_EMAIL=YOUR_EMAIL "--dart-define=DEV_PASSWORD=$loginPassword"
```

التصوير والموقع يحتاجان إذن المتصفح. جرى بناء هذا الجزء وتجربته للويب؛ تجهيز صلاحيات Android وiOS يحتاج مراجعة إعدادات كل منصة عند الانتقال إليها.

## الاختبارات والمعاينة

```powershell
flutter analyze --no-pub
flutter test --no-pub
flutter run -d web-server --web-port 5283 --web-hostname localhost -t test/proofs_preview.dart --no-pub
```

المعاينة الأخيرة تستخدم بيانات تجريبية داخل `test/`، ولا تتصل بحساب المستخدم أو قاعدة بياناته أو مزود الذكاء. لعرض مقاس جوال استخدم `?phone=1` قبل جزء المسار، ولعرض الأدمن استخدم `?admin=1`.

اختبارات Java تستخدم H2 المعزولة. يستثنى `AtahadApplicationTests` من التشغيل العام هنا لأنه يعتمد إعدادات قاعدة المشروع الحقيقية:

```powershell
.\mvnw.cmd -q '-Dtest=*Test,!AtahadApplicationTests' test
```

المعاينة البصرية واختبارات الواجهة لا تثبت توفر الكاميرا أو الموقع على كل جهاز، ولا نتيجة تحليل الصور الحية أو اتصال Gmail الحقيقي؛ تُجرب هذه الخدمات بحساب المستخدم بعد تشغيل النسخة الجديدة.
